Project Details

Project Overview

Build a responsive website using Tailwind CSS and an appropriate web-development workflow. Your site should communicate a clear topic to an identified audience.

Read the supporting Project Overview +

Compare the framework’s approach with the HTML and CSS principles you already know. Explain why your components, layout and interaction decisions fit the task.

Keep your design reference in Figma, develop the site in a GitHub repository, and publish a working deployment. Use AI critically and keep a record of what it contributed.

The twelve-week Schedule breaks the work into stages. The early checkpoints are opportunities to review progress, test assumptions and make changes before submission.

This is an illustrative BSc computing assessment. The dates, weights and requirements are examples rather than a live module brief.

Learning Outcomes Assessed

① Apply relevant methods and explain the evidence behind your decisions.

② Evaluate the implementation through testing and reflect critically on technical and AI-assisted decisions.

Key Expectations

Explain your framework decisions.+–

Show how your use of Tailwind CSS relates to layout, responsive behaviour and maintainable components. A framework is a method to evaluate, not evidence of quality on its own.

Use AI responsibly.+–

Record the tool, purpose and relevant output. Explain what you checked, modified or rejected. Verify generated code, inspect dependencies and test the resulting behaviour. Do not include private or sensitive information in prompts.

Your reflection should make your own judgement and contribution clear. The live module’s policy always takes precedence over this illustrative guidance.

Test with evidence.+–

Check the site with keyboard navigation and at narrow and wide screen widths. Record the issue, how you reproduced it, what you changed and the result of retesting.

Deliverables

Build the responsive website.+–

Submit a working deployment with meaningful page structure, responsive layouts and accessible navigation. Explain the framework and build tools you selected.

Include reusable components and consistent typography, spacing and states. Test the content and interaction on a phone as well as a laptop.

Connect the Figma design reference.+–

Provide a viewable Figma link showing the visual reference and component decisions that informed the implementation. Explain important differences between the design and the working site.

Publish and submit with GitHub.+–
  1. Create a repository for the assessment and add a README explaining the purpose, framework and local setup.
  2. Commit work in meaningful steps. Check the files before committing; exclude secrets, environment files and generated dependencies.
  3. Push the project to GitHub and connect the repository to your deployment service.
  4. Open the deployed site and test the main routes, keyboard access and mobile layout.
  5. Check that the lecturer can open the repository and deployment links, using the access arrangements specified for the assessment.
  6. Submit the repository URL, deployment URL and relevant final commit reference in the Submission Form.
Include the testing and AI-use record.+–

Show selected tests, issues and fixes. Include a concise AI-use record explaining what you verified and where your own decisions changed an output.

Reflect on the implementation.+–

Use the rubric to explain a strength, a limitation and a next step. Refer to concrete examples in the repository, testing record or deployed site.

Frequently Asked Questions

Finding an answer

Where should I start?+–

Read the overview and deliverables. Identify the first small action: choose a topic and outline what a reader needs to know. You can return to the complete requirements throughout the project.

What if I cannot finish every planned feature?+–

Make the core reading experience work, identify what is incomplete, and explain the limitations in your evidence and reflection. Use the published rubric to judge the implications.

Can I use a different technical approach?+–

For a live brief, discuss proposed changes with the lecturer. In this example, the important point is to make the reasoning and evidence visible rather than assume every tool is equally appropriate.

What is the difference between the checklist and rubric?+–

The checklist helps you confirm required items are present. The rubric describes the quality that the evidence should demonstrate.

How Work is Marked

What is looked at

Your evidence is judged against the published criteria and grade descriptions. A complete set of files is necessary, but it does not establish their quality.
